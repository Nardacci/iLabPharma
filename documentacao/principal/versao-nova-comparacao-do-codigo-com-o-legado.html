Versão nova: comparação do código com o legado

Resultado: o código dos módulos .NET da pasta labmedsys_web (retrato de 17/10/2026) é idêntico ao legado: das 11.705 arquivos-fonte comparados em 10 pastas (.cs, .aspx, .cshtml, .js, .sql e afins), 0 foram alterados. As únicas diferenças são dois arquivos de configuração de relatório (Settings.Designer.cs, CQ e GQ) que foram retirados por conterem nome de servidor e banco. Script: homologacao/ferramentas/comparar_legado_novo.py.

Por isso o retrato não ficou no repositório: seria uma cópia do que já está na raiz. Foi removido do commit (a cópia exigiu retirar 113 arquivos com senha, nome de servidor ou conexão; a lista de nomes está no histórico do git, no commit anterior).

O que a versão nova é, pelo que existe hoje

  • Um front-end novo em Angular 21 (Nardacci/iLabPharma-Novo, 107 arquivos, um commit) que substitui as telas .aspx. Telas prontas, todas do Principal: login, troca de senha, Perfis, Locais, Graus de contaminação e Centros de custo. Há serviços de acesso à API para usuários, contas de usuário, grupos, notificações padrão e GST, mas ainda sem tela. As demais rotas são "placeholder", com um mapa de cada tela .aspx do legado para a rota nova.
  • O front-end chama uma API REST (/api/perfis, /api/locais, /api/centros-custo, /api/graus-contaminacao, /api/grupos-usuario, /api/auth/...).
  • Essa API não está no código que temos. A API do Principal do legado (LabMedSys.Principal.Service.UI) tem controladores de Ambiente, Área, Autenticação, Equipamento, Função profissional, Local, Notificação, Pessoa jurídica, Usuário e outros, mas não tem Perfil, Centro de custo, Grau de contaminação nem Grupo de usuário. Ou seja, a API que o Angular espera existe em outro lugar, e é nela que está a parte realmente nova.

Correção (17/10/2026, após a rodada 1 do Principal): o repositório iLabPharma-Novo no GitHub estava atrás do ambiente. No ambiente (https://10.1.30.179), 22 telas do menu abrem com lista e pesquisa (só Microservices é placeholder), e o menu da GQ já existe com telas em placeholder. A lista de seis telas acima vale para o retrato do GitHub, não para o ambiente.

Consequências para o teste

  1. Regras de negócio e banco são os mesmos do legado, enquanto a API nova não mudar o contrário. Os desvios conhecidos do legado (por exemplo, exclusão sem justificativa) devem aparecer também na versão nova, se a API nova reaproveita a regra.
  2. A regressão se concentra no front-end e na API nova: o que o Angular mostra, valida e grava, comparado com a tela .aspx do mesmo cadastro.
  3. Só dá para testar hoje as telas que existem no Angular (lista acima). O resto é "ainda não implementado".
