DV-PRI-050 · Login redireciona para qualquer endereço informado em "urldesenv" e acrescenta o token da sessão

Alta Aberto acesso/segurança ver o defeito completo

Detalhes

Se o endereço da tela de entrada leva o parâmetro `urldesenv`, o sistema, depois de um login correto, manda o navegador para esse endereço com `?token=<token da sessão>` no fim. O código não confere se o destino é do próprio sistema (`Default.aspx.cs`, trecho do redirecionamento). Quem enviar a um usuário um link de login com `urldesenv` apontando para um site seu recebe o token dele. Foi testado só com um destino do próprio ambiente (devolveu a página pedida com o token no endereço); **não foi testado destino de fora**, para não enviar o token a terceiros.

Como reproduzir

  1. Abrir a tela de entrada com `urldesenv` apontando para uma página do próprio sistema (inexistente).
  2. Entrar com um usuário válido.
  3. Observar o endereço final (sem copiar o token).

Esperado

Ignorar `urldesenv` ou aceitar só destinos de uma lista do sistema.

Obtido

Redirecionou para o endereço informado, com o token anexado (36 caracteres).

DV-PRI-015 · As mensagens de login revelam se o usuário existe

Média Aberto acesso/segurança ver o defeito completo

Detalhes

Quando o login digitado não existe, a tela diz **"O usuário informado é inválido!"**. Quando o login existe e a senha está errada, diz **"A senha está incorreta, você tem mais N tentativa(s) antes de sua conta ser bloqueada!"**. Qualquer pessoa pode, portanto, descobrir quais logins são válidos e depois só tentar senhas para eles. **Risco:** facilita o ataque por tentativa de senha. O bloqueio após 4 erros reduz o risco, mas também permite bloquear de propósito a conta de outra pessoa.

Como reproduzir

  1. Abrir a tela de login do **Principal**.
  2. Digitar um login que não existe, qualquer senha, e clicar em entrar: anotar a mensagem.
  3. Digitar o login de um usuário de teste que existe, com a senha errada: anotar a mensagem.

Esperado

Mensagem única nos dois casos, por exemplo "Usuário ou senha inválidos" (CT-PRI-003; RN-PRI-002; RF-PRI-003).

Obtido

Duas mensagens diferentes, uma para usuário inexistente e outra para senha incorreta.

DV-PRI-016 · A contagem de tentativas restantes no login está errada: o usuário é bloqueado um erro antes do que a tela anuncia

Baixa Aberto acesso/segurança ver o defeito completo

Detalhes

Nos quatro primeiros erros de senha, a tela avisa "mais 4, 3, 2 e 1 tentativa(s)", mas o usuário **é bloqueado no 4º erro**: na 4ª mensagem ainda diz "mais 1 tentativa" e a quinta tentativa, mesmo com a senha certa, é recusada ("O usuário informado foi bloqueado devido o limite de tentativas de acesso ao sistema!"). **Risco:** baixo, mas o usuário é pego de surpresa e a informação da tela não bate com a regra real.

Como reproduzir

  1. Abrir a tela de login do **Principal**.
  2. Com o login de um usuário de teste ativo, errar a senha quatro vezes seguidas, anotando cada mensagem.
  3. Na quinta tentativa, usar a senha correta.

Esperado

Mensagens com a contagem correta de tentativas restantes (3, 2, 1 e 0 na última), e o bloqueio acontecendo quando a contagem chega a zero.

Obtido

Mensagens com 4, 3, 2 e 1; bloqueio no 4º erro; a senha correta na 5ª tentativa é recusada.
