Versão nova: como usar esta seção

Para quem é

  • Desenvolvimento: cada tela tem o que corrigir e o comportamento esperado, com o defeito de origem.
  • Qualidade e homologação: cada tela tem o passo a passo, os usuários e os dados de teste.
  • Gestão: cada tela tem a situação e o risco em poucas linhas.

Como ler uma tela

  1. Resumo geral: o que a tela faz, a tabela de casos, os defeitos, e três blocos curtos (para quem desenvolve, para quem testa e para a gestão).
  2. Passo a passo de homologação: pré-requisitos, passos numerados com o que deve aparecer, como registrar e uma tabela de resultados para preencher.

O que significam as classes

Classe Significa
Igual Mesmo comportamento do sistema entregue, inclusive a falha conhecida
Regressão Funcionava no sistema entregue e na versão nova funciona pior
Melhoria Falhava no sistema entregue e agora funciona
Novo O sistema entregue não tinha resultado para o caso
Bloqueado Não deu para executar (falta usuário, perfil ou dado)

Dados e usuários de teste

  • Os registros de teste começam com T.. Os dados ficam no ambiente, sem limpeza.
  • Os usuários t.* (administrador, consulta, cadastro e outros) e os perfis 0.T.* estão descritos na página "Usuários de teste". O prefixo 0. do perfil existe porque a Conta usuário mostra só os 10 primeiros perfis.
  • O processo para criar um usuário é: Profissional (Incluir) → Conta usuário (login e validade) → Perfis (permissão).
  • As regras do banco e do servidor são as mesmas do sistema entregue; o que muda é o front-end e a API nova. Por isso uma falha antiga que continua é esperada, e a regressão é o que mais importa.

Ordem sugerida de homologação

  1. Acesso ao sistema (Login e Troca de senha).
  2. Administração: Perfil, Profissional e Conta usuário (permitem criar os outros usuários).
  3. Cadastros testados: Estrutura funcional, Centro de custo, Pessoa jurídica, Ambientes e Equipamentos.
  4. Tabelas de apoio.
  5. Telas ainda não testadas, com o roteiro padrão de cadastro.
